Re-run the Grep-replacement benchmark with two defects corrected. The previous pass ran end to end and then honestly reported that it could not measure anything: retention was fine at 11,773 of 13,327 Grep calls, but the **scored population collapsed to 20 queries**, with recall computed on 12.

Read first: `exploratory/retrieval/RESULTS.md` and `instruments/retrieval/SPEC.md`. The specification is otherwise sound — the labels, the arms, the tokenisation rules, the metrics, the reporting order all stand.

## Defect 1 — the scope was wrong, and it was the specification's fault

The spec said to index `toolsenabled-current` "since it is where the queries come from." That is false. The queries are spread across several distinct trees. Measured distribution of query scope across the eval set: `toolsenabled/opensource/wt-capability`, plain `toolsenabled`, `toolsenabled-current` and several of its subdirectories, plus temporary checkouts. Almost every query fell outside the single indexed tree.

**Fix:** index every tree that queries actually target, and score each query against the index for *its own* tree. Derive the tree set empirically from the eval set's `cwd` and query `path` fields rather than assuming. Report the resulting scored population per tree and in total, and report how many queries still fall outside any indexed tree.

## Defect 2 — no commit SHA, so every query was scored against today's HEAD

The previous report states: "None of the transcript records carries an explicit commit SHA, so all 20 scored records are HEAD fallbacks." Any file that changed between the query and now introduces error.

**Fix:** reconstruct tree state by timestamp. Transcript records carry `timestamp` and `gitBranch`, and the repositories have history, so for each query select the commit on that branch closest in time at or before the query. Report, per query, whether an exact-time reconstruction was possible or a fallback was used, and give the distribution of time gaps between query and chosen commit. Where a repository is not a git checkout, say so and fall back with the count reported.
